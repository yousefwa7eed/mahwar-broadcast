## 1) ملخص تنفيذي

التطبيق مبني بطريقة تحترم أغلب مطالب المتاجر: أذونات ضيقة (لا SMS، لا سجل مكالمات، لا موقع في
الخلفية)، سياسة خصوصية داخل التطبيق، حذف حساب موجود، ودفع نقدي خارج التطبيق (وهو المسموح
والمطلوب لخدمة ميدانية).

**العائقان الفعليان اليوم هما P0-2 وP0-3** (روابط الويب العامة، والإبلاغ/الحظر). P0-1 رُوجع
وأُغلق: الحذف كان يعمل، ثم وُحِّد تأكيده مع الدخول الهاتفي.

| # | العائق | المتجر المتأثر | الحالة |
|---|---|---|---|
| P0-1 | حذف الحساب — **تصحيح للقراءة الأولى:** الحذف لم يكن معطّلًا. كل حسابات التطبيق تُنشأ ببريد + كلمة مرور (البريد اختياري، والفارغ يصبح `<الهاتف>@mahwar.app`)، فمسار كلمة المرور القديم كان يعمل | آبل 5.1.1(v) + جوجل «account deletion» | **مُغلق أصلًا، ثم وُحِّد مع الدخول الهاتفي** — التأكيد الآن برمز OTP يُتحقق منه خادميًا ويمكن الرجوع لكلمة المرور إن لزم؛ الدالة v22 (11 نوفمبر 2026) |
| P0-2 | لا توجد روابط ويب عامة لسياسة الخصوصية/الشروط/حذف الحساب — النص داخل التطبيق فقط، والمتجران يطلبان URL عامًا حيًّا | الاثنان | مفتوح — الموقع التعريفي قيد التصميم، والصفحات الثلاث مطلوبة قبل الإرسال |
| P0-3 | لا وسيلة «إبلاغ عن محتوى» أو «حظر مستخدم» للتقييمات والتعليقات العامة والصور | آبل 1.2 + جوجل UGC | مفتوح — السياسة الجديدة تتعهّد بالإبلاغ خلال 72 ساعة، والواجهة لم تُبنَ بعد |

## 3) ما يفعله التطبيق فعلًا (الحقيقة التي تُقارَن بها السياسة)

### 3.1 البيانات المخزّنة

| المصدر | الحقول | ملاحظة |
|---|---|---|
| `profiles` | الاسم، الهاتف، بريد اختياري، **الرقم القومي**، الدور، اللغة، `avatar_id`، `fcm_token`، `device_id`، وقت تأكيد الهاتف | الرقم القومي مطلوب قبل إرسال طلب خدمة (`needNationalIdFirst`) |
| `vehicles` + `orders` | الماركة/الموديل/السنة/الفئة/اللون، حروف وأرقام اللوحة | |
| `orders` | الموقع (lat/lng)، العنوان النصي، ملاحظات، **مرفقات صور**، السعر، الحالة، هواتف | |
| `ratings` | نجوم + **تعليق عام** + `user_id` + `provider_id` | يُعرض في بروفايل المزوّد، ومتوسط 30 يومًا |
| `support_tickets` | موضوع، نص، اسم، هاتف، تصنيف، **صورة مرفقة**، رد الإدارة | + بريد إلى صندوق الشركة |
| `device_tokens` / `notifications` | رمز FCM، معرّف الجهاز، المنصة، آخر ظهور، بيانات الإشعار | |
| `page_views` | اسم الشاشة، وقت الدخول، مدة البقاء | تحليلات داخلية |
| `sms_send_logs` | رقم الهاتف، نوع الرسالة، النتيجة، الوقت | تشغيل وحصص |
| `admin_audit_log` | إجراءات المشرفين | |

**لا يوجد:** مدفوعات داخل التطبيق، تتبّع إعلاني، بيع بيانات، قراءة SMS أو سجل المكالمات، أو أذونات
جهات اتصال. الصور والأفاتار: الأفاتار يُختار من كتالوج جاهز (ليس رفعًا)، والصور تُرفع للطلبات والدعم.

### 3.4 حذف الحساب

**قبل التعديل:** `delete-account` كان يطلب كلمة المرور الحالية ويتحقق منها على الخادم بعميل معزول.
وكل حسابات التطبيق تُنشأ ببريد + كلمة مرور — حقل البريد اختياري في التسجيل، وإن تُرك فارغًا يصبح
`<الهاتف>@mahwar.app` — لذلك **كان الحذف يعمل فعلًا** لكل مستخدمي التطبيق.

**بعد التعديل (11 نوفمبر 2026):** الحوار يرسل رمز OTP إلى رقم المستخدم المسجّل، ثم يرسل
`{ otp }` إلى الدالة. الدالة تتحقق من الرمز **على الخادم** بعميل معزول
(`verifyOtp({ phone, type: 'sms' })`) وتقارن معرّف المستخدم العائد بمعرّف صاحب الجلسة قبل أي
تنظيف أو حذف، وتعيد `OTP_REQUIRED` / `INVALID_OTP` / `RATE_LIMITED` /
`PHONE_VERIFICATION_UNAVAILABLE` عند الرفض. لا يُقبل أي إثبات تحقق من العميل.

**لماذا:** شاشة الدخول أصبحت هاتفية/OTP أولًا، والمستخدم قد لا يتذكّر كلمة المرور التي كتبها وقت
التسجيل؛ إثبات ملكية الهاتف خادميًا هو تأكيد أقرب لطبيعة الحساب، والمتجران يقبلان أي طريقة تأكيد
طالما الحذف يبدأ من داخل التطبيق.

**حدود معروفة:** الحساب الذي لا رقم هاتف له على مستوى `auth.users` لا يستطيع الحذف من التطبيق
(`PHONE_VERIFICATION_UNAVAILABLE`). في المشروع الحيّ اليوم حسابان بهذه الصورة فقط: حساب إدارة
(بيانات اعتماد بريد/كلمة مرور، لا يدخل التطبيق أصلًا) وحساب اختبار قديم بلا دور.

**يبقى كما هو:** `cleanup_user_data` يحذف الإشعارات والطلبات وتخصصات المزوّد وتفاصيل سيارته وسجل
المزوّد والسيارات والبروفايل، **ولا يمس** `ratings` و`support_tickets` و`sms_send_logs` وملفات
التخزين — وهذا موثَّق الآن صراحةً في سياسة الخصوصية (احتفاظ مجهول الهوية).

## 4) جوجل بلاي — ما يجب أن يتحقق

1. **حذف الحساب**: مسار داخل التطبيق + رابط ويب عام يعمل بلا تسجيل دخول، يشرح ما يُحذف وما يُحتجز.
2. **سياسة خصوصية**: حقل إلزامي في Console ورابط عام حي (ليس PDF ولا خلف تسجيل دخول).
3. **Data safety**: يجب أن يطابق المانيفست والـSDK حرفيًا — الهاتف، الاسم، **الموقع الدقيق**، الصور،
   معرّف المستخدم، معرّفات الجهاز/رمز الدفع، بيانات الاستخدام. عدم التطابق = رفض ثم إيقاف.
4. **الأذونات**: `READ_MEDIA_IMAGES` يحتاج مبررًا/إقرارًا؛ البديل الموصى به **Photo Picker**.
   مجموعتا SMS وسجل المكالمات محظورتان (غير موجودتين عندنا — جيد).
5. **UGC**: إبلاغ + حظر + شروط غير متسامحة + إشراف بزمن استجابة.
6. **الإصدار**: `targetSdk 36` (إلزامي للأهداف الجديدة منذ 31 أغسطس 2026) + النشر بصيغة AAB.

## 5) آبل — ما يجب أن يتحقق

1. **5.1.1(v)**: الحذف يبدأ من داخل التطبيق، ويقبل النص صراحةً تأكيدًا بـ**رمز يُرسل إلى رقم الهاتف**
   — وهو ما طُبّق الآن (كان اشتراط كلمة مرور غير موجودة خطأ تصميمي).
2. **5.1.1(i)**: رابط الخصوصية في App Store Connect **و**داخل التطبيق، مع بند احتفاظ وأطراف ثالثة.
3. **5.1.1(ii)**: نصوص الأذونات محدّدة لا قوالب؛ إعلان الميكروفون بلا استخدام يُسأل عنه، ونقص مفتاح
   لـAPI مستخدم = `ITMS-90683` رفض آلي.
4. **App Privacy labels**: الهاتف/الاسم، الموقع الدقيق، محتوى المستخدم (صور وتعليقات)، معرّف المستخدم،
   بيانات الاستخدام — كلها **مرتبطة بالمستخدم**، والتتبّع = لا.
5. **1.2**: إبلاغ + **حظر مستخدم** + تواصل منشور + إشراف؛ غياب الحظر سبب رفض شائع.
6. **3.1.1**: الدفع النقدي للخدمة الميدانية مسموح بلا IAP (وممنوع IAP له). أي ترقية رقمية لاحقًا تلزمها IAP.
7. **2.1**: المراجع لا يستطيع استلام SMS مصري — يلزم حساب مراجعة برمز ثابت/رقم دولي + حسابين
   (عميل ومزوّد) + خطوات مكتوبة.

## 8) أسباب الرفض الأكثر احتمالًا (مرتبة)

1. تعذّر تقييم التطبيق لأن المراجع لا يستلم OTP — آبل 2.1.
2. غياب الإبلاغ/الحظر للتقييمات — آبل 1.2، جوجل UGC.
3. حذف حساب لا يعمل — آبل 5.1.1(v)، جوجل account deletion **(أُصلح في الكود)**.
4. رابط سياسة خصوصية غائب/404 أو ناقص — الاثنان.
5. Data safety لا يطابق المانيفست — جوجل.
6. إذن مكتبة صور واسع أو ميكروفون بلا استخدام — الاثنان.
