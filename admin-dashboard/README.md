# برج مراقبة محور — لوحة الأدمن

لوحة ويب مستقلة تمامًا عن تطبيق ماحور: دخول إيميل + TOTP (2FA إلزامي على مستوى قاعدة البيانات)،
كل الاستدعاءات RPCs للقراءة فقط محمية بـ `is_admin()` (قائمة أدمن + aal2).

## الميزات (المرحلة 5A — قراءة فقط)
- عدادات المستخدمين والطلبات (24 ساعة / 7 أيام + الحالات).
- قائمة مستخدمين: بحث (إسم/موبايل/إيميل/آخر 4 أرقام قومي)، ترشيح بالنوع، تقسيم صفحات.
- تفاصيل مستخدم: بياناته، سيارات، بيانات مقدم الخدمة، آخر 20 طلب، تقييمات، عمليات الأدمن عليه.
- كشف الرقم القومي الكامل: **سبب إلزامي + تسجيل تلقائي** في `admin_audit_log`.
- تصدير CSV: **مُدقق** (تسجيل تلقائي، سقف 5000 صف، الرقم القومي مقنّع).

## التشغيل محليًا
1. انسخ `.env.example` إلى `.env` واملئه من إعدادات المشروع (قيم عامة).
2. `npm install` ثم `npm run dev`.

## النشر على Vercel
1. ارفع الريبو على GitHub.
2. Vercel → Add New Project → Import → **Root Directory:** `admin-dashboard`.
3. Framework: Vite (تلقائي) — Build: `npm run build` — Output: `dist`.
4. Environment Variables: `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY`.
5. Deploy.

## خطوات تأمين أول استخدام (مرة واحدة)
1. سجل حساب أدمن من شاشة "إنشاء حساب أدمن" (الخادم يمنع إنشاء بروفايل تطبيق للحساب ده).
2. فعّل البريد الإلكتروني (Pirl confirmation email أو اعطل التأكيد من Auth settings لعكسه حسب تفضيلك).
3. سجل دخول → فعّل التحقق بخطوة إضافية على **جهازين** (Supabase ما عنده أكواد استرجاع).
4. أعطِ الحساب صلاحية أدمن (SQL editor):
   `insert into public.admins (user_id) values ('<USER_ID>') on conflict do nothing;`
5. أعد الدخول — اللوحة هتفتح.

## التراجع عن أي عملية
كل العمليات الحساسة المدعومة في `admin_audit_log` (action/details/created_at/admin).
